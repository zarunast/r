# АИС приёмной комиссии БГТУ

Рабочий backend на Python 3.11+ / FastAPI / SQLAlchemy 2 / SQLite по приложенному ТЗ.
Два сайта используют один REST API: служебные методы требуют JWT,
`/public/*` возвращают только обезличенные данные. Внутренний сайт на React 18 + TypeScript
включён в `frontend/`: дашборд, реестр, рейтинги, договоры, звонки, отчёты и журнал действий.
Публичный портал абитуриента доступен на `/abiturient/`: поиск ЕПГУ, каталог,
обезличенные рейтинги, объяснение текущего положения и чат-помощник без входа.

## Запуск

```bash
cd /workspace/r
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
export DATABASE_URL=sqlite:///data/admissions.sqlite3
# Сгенерируйте один раз и сохраните в защищённом окружении службы:
export JWT_SECRET="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))')"
.venv/bin/python -m admissions init-db
.venv/bin/python -m admissions create-user secretary
# Сборка внутреннего сайта (Node.js 20.19+ или 22.12+):
cd frontend
npm ci
npm run build
cd ..
.venv/bin/uvicorn admissions.api:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Пароль вводится скрыто, не передаётся в аргументах команды. Swagger доступен на пути
`/docs` запущенного сервера. В Authorize введите логин и пароль созданного пользователя.
Никаких стандартных учётных записей или секретов в коде нет. `.env` автоматически не
читается: переменные нужно передать через оболочку, systemd EnvironmentFile или Docker.
Для отдельной локальной базы можно передать `--database sqlite:///data/demo.sqlite3`
перед подкомандой CLI. Сайт открывается на корневом пути `/` этого же сервера.
Сначала доступен явно обозначенный демо-режим на вымышленных данных; кнопка
«Подключить рабочую базу» открывает вход с созданной учётной записью.

## Импорт вашей выгрузки

```bash
.venv/bin/python -m admissions import-epgu /путь/к/выгрузка.xlsx --year 2026
```

Либо `POST /imports/epgu?year=2026` с multipart-полем `file` и Bearer-токеном.
Для нескольких листов укажите `sheet`. Проверка: `GET /reports/statistics?year=2026`.

Ваш файл содержит 19 610 заявлений от 3 506 человек, а не 19 610 разных абитуриентов.
В нём смешаны бакалавриат, магистратура, аспирантура и разные формы обучения.
Уникальный ключ заявления: номер абитуриента + год + кампания + направление + форма + квота.
Номер хранится строкой, включая ведущие нули. Числовые номера в Excel отклоняются,
так как их исходную длину восстановить достоверно нельзя.

Гибкое сопоставление заголовков находится в `admissions/importer.py: ALIASES`.
Неизвестная категория/статус, невалидные баллы и повтор заявления попадают в отчёт
с номером строки. Корректные строки сохраняются одной транзакцией; ошибка БД откатывает
весь импорт. CLI возвращает код 2, если есть ошибочные строки, даже при успешном
импорте остальных. Отсутствующие в новом файле заявления не удаляются и не отзываются
автоматически: файл может быть частичным. Отзыв выполняется явным изменением статуса.

«Сумма баллов» считается готовым итогом, включая ИД: например, 278, а не сумма всех
предметных колонок. Альтернативные предметы и внутренние экзамены сохраняются отдельно.
Для ручного создания/пересчёта передавайте в `exam_scores` только предметы, выбранные
для данного конкурса; тогда итог = сумма выбранных экзаменов + ИД. Льготы балл не меняют.

Неизвестные дополнительные столбцы сохраняются в `Application.source` и доступны только
сотрудникам. Паспорт, СНИЛС, образование и контакты находятся в `Applicant.profile`;
данные родителя можно добавить туда через PATCH. Импорт сохраняет локальные поля профиля.
Если персональные данные одного человека в строках файла расходятся, используется последняя
строка, а отчёт содержит предупреждение. Повтор неизменённого файла не меняет данные.

## Возможности API

| Группа | Методы и поведение |
|---|---|
| Авторизация | `POST /auth/token`, bcrypt, JWT на 8 часов; отключённый пользователь теряет доступ |
| Реестр | `GET/POST /applicants`, `GET/PATCH /applicants/{number}`; поиск по ФИО, номеру, году, договору |
| Заявления | `POST /applications`, `PATCH /applications/{id}`; статусы и пересчёт баллов |
| План мест | `PUT /seat-plans`; год, кампания, направление, форма, квота, количество мест |
| Рейтинги | `GET /public/rankings`; сразу пять списков одного конкурса |
| Абитуриент | `GET /public/applicants/{number}?year=2026`; место и объяснение прогноза |
| Договор | `POST /contracts`, `PATCH /contracts/{id}`, `GET /contracts/{id}/history` |
| Word | `POST /contracts/{id}/document`; multipart `template` с пользовательским DOCX |
| Оплата | `POST /imports/payments`; multipart `file`, Excel со столбцами «Номер договора», «Оплачен» |
| Обзвон | `GET /calls/queue?year=...&change_deadline=...&payment_deadline=...`, `POST /calls` |
| Зачисление | `POST /applications/{id}/enroll`; номер приказа и дата, проверки согласия/договора |
| Отчёты | `GET /reports/statistics`, `/reports/ranking` (xlsx/pdf), `/reports/accounting` (xlsx) |
| 1С | `GET /exports/1c?year=2026&format=json` или `xml`, только после внесённого приказа |
| Чат-бот | `GET /public/faq?question=...`; локальные правила без внешнего API |
| Состояние | `GET /health`; проверяет запрос к БД |

Параметры рейтинга: `year`, `direction`, `campaign`, `study_form`; для отчёта дополнительно
`quota` и `format`. Полная спецификация запросов автоматически доступна через OpenAPI.
Одинаковые баллы получают одинаковое место; порядок внутри ничьей стабилен по номеру.
Правила преимущественного права/БВИ и официальное разрешение ничьих нужно отдельно
согласовать с правилами приёма. По такому рейтингу нельзя автоматически издавать приказ.

Категории: `special` (особая), `separate` (отдельная), `target` (целевая), `general`
(общий конкурс), `paid` (платная). В примере есть только `бюдж` и `плат`; флаги ОВП/ВПП
не используются для угадывания квоты. В ТЗ СВО названо особой квотой; соответствие
юридических оснований категориям требует уточнения до реального приёма. Ядро принимает
явные категории, не делает выводов о льготах по свободному тексту документов.

Пример ручного заявления:

```json
{
  "applicant_number": "001234567", "year": 2026, "campaign": "бак",
  "direction": "Информатика", "study_form": "Очная", "quota": "general",
  "exam_scores": {"Русский язык": 80, "Математика": 85, "Информатика": 90},
  "achievements": 5, "priority": 1, "consent": true
}
```

## Договоры и документы

Местоположение (`location`) и этап (`stage`) независимы.
Места: `admissions`, `applicant`, `accounting`, `archive`.
Этапы: `draft → issued → signed → registered`; из любого действующего этапа допустим
`cancelled`. Каждое изменение, включая подтверждение оплаты, хранится с временем и автором.
Нельзя подтвердить оплату отменённого договора. Отсутствие договора в файле бухгалтерии
или строка «НЕТ» не сбрасывают ранее подтверждённую оплату. Реестр бухгалтерии должен
содержать именно подтверждения полной оплаты; суммы и частичные платежи здесь не сверяются.

Поддерживаемые маркеры Word: `{{contract_number}}`, `{{applicant_number}}`, `{{full_name}}`,
`{{direction}}`, `{{study_form}}`, `{{year}}`, `{{snils}}`, `{{passport_series}}`,
`{{passport_number}}`, `{{date}}`. Замена работает в абзацах, таблицах, колонтитулах и
при разбивке маркера на несколько Word-runs; оформление изменённого абзаца берётся из
первого run. Текстовые поля/фигуры Word не поддерживаются. Юридический шаблон предоставляет вуз.

Пакет 1С имеет версию схемы `1`, но конкретный формат интеграции нужно согласовать
с конфигурацией 1С университета. Автоматическая отправка в 1С не выполняется.

## Прогноз и обзвон

Прогноз — прозрачная оценка текущего положения: `within_seats`, `outside_seats`,
`tie_at_boundary` или `unknown`. Без плана мест он не выдаёт оценку. Числовая вероятность
не выдумывается (`probability: null`). Для обученной модели нужны история зачислений,
разметка и проверка качества; внешние ИИ-сервисы и отправка им персональных данных не включены.

Обзвон активируется в интервале от 7 дней до указанного срока включительно. Из очереди
исключаются оплаченные/отменённые договоры и заявления с последним результатом `declined`.
Приоритет — сумма признаков: согласие 40, первый приоритет 25, подписанный или
зарегистрированный договор 30. Это эвристика интереса, не статистическая вероятность.
Один человек может встретиться в очереди несколько раз по разным платным заявлениям.

## Безопасность и эксплуатация

Запускайте сервер с `umask 077`, храните БД и резервные копии на защищённом диске;
SQLite сам по себе не шифрует персональные данные. Загруженный пример содержит ПДн,
он не включён в исходники и архив проекта. Валидирующая база в `data/` игнорируется Git.

По умолчанию служебные методы доступны только с loopback и требуют JWT. Для прямого
доступа из локальной сети укажите `INTERNAL_NETWORKS`, например `10.20.0.0/16,127.0.0.0/8`.
При размещении за Nginx обязательно ограничьте служебные пути сетью вуза **на Nginx**:
backend увидит адрес самого прокси. Для открытого портала разрешайте только `/public/`,
страницу `/abiturient/`, `/assets/` и favicon; не публикуйте целиком upstream.
Пример фрагмента (замените подсеть реальной):

```nginx
client_max_body_size 25m;
location = /abiturient { return 301 /abiturient/; }
location = /abiturient/ { proxy_pass http://127.0.0.1:8000; }
location /assets/ { proxy_pass http://127.0.0.1:8000; }
location = /favicon.svg { proxy_pass http://127.0.0.1:8000; }
location /public/ {
    limit_req zone=public_api burst=20 nodelay;
    proxy_pass http://127.0.0.1:8000;
}
location / {
    allow 10.20.0.0/16;
    deny all;
    proxy_pass http://127.0.0.1:8000;
}
```

`limit_req_zone $binary_remote_addr zone=public_api:10m rate=10r/s;` задайте в блоке
`http`. Также нужны HTTPS и ограничение частоты `/auth/token`. API не интерпретирует
ввод как HTML; React-интерфейсы выводят строки обычным текстом без
`dangerouslySetInnerHTML`. Экспорт Excel экранирует формулы. Имя, контакты, исходная строка,
документы и данные договора не попадают в публичные сериализаторы.

Схема создаётся через `create_all` для первой версии. Alembic-миграции пока не добавлены;
обновления структуры существующей БД требуют отдельной миграции. Данные не удаляются
автоматически, поиск по предыдущим годам работает на общем реестре. Политика удаления
после 6 лет, аудит изменений карточек и юридическая проверка 152-ФЗ — задачи внедрения.

## Резервное копирование и восстановление

```bash
.venv/bin/python -m admissions backup backups/admissions-2026-08-01.sqlite3
```

Используется SQLite Backup API, копирующий согласованную БД с учётом WAL;
копия проверяется `PRAGMA integrity_check`, существующий файл не перезаписывается.
Ежедневный запуск нужно зарегистрировать у системного планировщика сервера, например
в cron (часовой пояс `Europe/Moscow`, каталог `/workspace/r`):

```cron
0 2 * * * cd /workspace/r && .venv/bin/python -m admissions backup "backups/admissions-$(date +\%F).sqlite3"
```

Cron/службы этим проектом автоматически не устанавливаются. Проверять хранение копий,
свободное место и доставку ошибок должен администратор. При восстановлении остановите
API, сохраните текущую БД и её WAL/SHM, проверьте копию, замените файл БД копией,
удалите только старые относящиеся к заменённой БД WAL/SHM и запустите API.

Фоновый ночной пересчёт прогнозов не требуется текущей реализации: прогноз вычисляется
из актуальной БД при запросе. Отдельного обучаемого ночного ИИ-процесса нет.

## Проверка

```bash
.venv/bin/python -m pytest -q
```

Тесты используют временные БД и синтетические ПДн. Проверяют повторный импорт,
разделение заявлений, семантические заголовки, ошибки, рейтинги с ничьими, договор,
оплату, DOCX/PDF/Excel, backup, откат транзакции, JWT, сетевое ограничение, публичную
сериализацию, зачисление и выгрузку в 1С. Проверка настоящего Excel описана в `VALIDATION.md`.
Нагрузочные гарантии из ТЗ (500 одновременных запросов и временные нормативы) пока
не подтверждены; SQLite использует WAL, индексы и короткие транзакции.

## Структура

`db.py` — Unit of Work; `models.py` — сущности; `importer.py` — Excel и upsert;
`services.py` — правила конкурса, документы, отчёты, резервные копии;
`security.py` — учётные записи и JWT; `api.py` — REST и валидация; `__main__.py` — CLI.
`web.py` — защищённые представления внутреннего сайта; `frontend/` — React-интерфейс.
`portal.py` — открытый каталог конкурсов; `frontend/src/portal/` — отдельное приложение абитуриента.

Связи: `Applicant 1—N Application`, `Application 1—0..1 Contract`,
`Contract 1—N ContractEvent`, `Application 1—N Call`. `SeatPlan` относится к полному
ключу конкурса, `User` хранит только хеш пароля и статус доступа. Год хранится в
заявлении, поэтому история нескольких приёмных кампаний не перезаписывается.
