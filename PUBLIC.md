# Портал абитуриента БГТУ

Второй сайт общей АИС: открывается без логина и использует ту же SQLite-базу,
что и внутренний сайт приёмной комиссии. Персональные карточки остаются в закрытом API.

## Оформление

Реализованы университетская шапка, сине-белая палитра, жёлтые акценты,
главный баннер, поиск по номеру ЕПГУ, карточки направлений, конкурсные таблицы,
пошаговый путь поступления, FAQ и подвал с официальными ссылками.
Знак «Б» и инженерная иллюстрация созданы в SVG. Шрифт и иконки загружаются локально.
Макеты адаптированы для десктопа и мобильного экрана; есть переключатель контраста и размера текста.

Референс пользователя: https://www.tu-bryansk.ru/abiturient/ . Прямой просмотр этой
страницы из облачной среды заблокирован сетевой политикой (CONNECT 403), поэтому
точное соответствие исходным цветам, шрифтам, логотипу и структуре не проверено.
Текущее оформление — самостоятельная университетская стилизация.
В черновик сетевых настроек добавлены только `www.tu-bryansk.ru` и `tu-bryansk.ru`,
остальные настройки сохранены. Для применения изменения нужно проверить, сохранить
и опубликовать среду в её настройках; само сохранение черновика доступа не открывает.

## Запуск двух сайтов

```bash
cd frontend
npm ci
npm run build
cd ..
# DATABASE_URL и JWT_SECRET задаются по README.
.venv/bin/uvicorn admissions.api:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers
```

После запуска:

- `/` — внутренний сайт сотрудников;
- `/abiturient/` — настоящий открытый портал без авторизации;
- `/abiturient/?demo=1` — явная демонстрация на вымышленных данных;
- `/docs` — документация API.

Для разработки `npm run dev` из `frontend`: сайт сотрудников находится на `/`,
портал — на `/abiturient.html`. Vite проксирует `/api/*` в Python на порту 8000.
Сборка содержит два HTML-файла с отдельными приложениями. Чувствительные данные
и токены сотрудников в приложение портала не передаются.

Это локальные пути запущенного сервера, не публичный интернет-хостинг.
Для внешнего доступа нужен сервер/домен и reverse proxy с HTTPS. Пример разделения
публичных и служебных путей приведён в README. Не открывайте служебные методы всей сети.

## Возможности

| Функция | Поведение |
|---|---|
| Мой конкурс | Поиск по номеру ЕПГУ и году, ведущие нули сохраняются |
| Мои заявления | Направления, формы обучения, категории, итоговые баллы, место, план мест |
| Оценка положения | В пределах мест / за пределами / ничья на границе / недостаточно данных |
| Объяснение | Модальное окно с факторами, без выдуманных процентов и гарантий поступления |
| Каталог | Фильтры уровня образования, поиск названия/кода, бюджетные и платные группы различаются |
| Конкурсные списки | Пять категорий, выбор группы, поиск номера, 15 строк на странице, выделение своего номера |
| CSV | Анонимный список выбранной категории; экспорт не требует входа и не содержит ФИО |
| Как поступить | Путь из четырёх шагов и ссылки на Госуслуги и официальные правила БГТУ |
| Помощник | Вопросы о номере, документах, рейтинге, оценке шансов и сроках; локальные правила |
| FAQ | Раскрывающиеся ответы, пояснения о публичных данных и статусе рейтинга |
| Мобильный вид | Меню, поиск, карточки, локальная прокрутка таблиц, чат с клавиатурным фокусом |

Сроки кампании, цена обучения и контакты не выдумываются: для них даны ссылки на
официальную страницу комиссии. Портал не принимает заявления, согласия или платежи.
Отсутствие данных, плана мест и неизвестный номер отображаются как отдельные состояния.
Ошибка настоящего сервера не заменяется демонстрационными значениями.

## Данные и приватность

Используются только открытые методы:

- `GET /public/catalog?year=2026` — конкурсные группы, код/название программы,
  опубликованные категории, план мест и количество действующих заявлений;
- `GET /public/rankings` — обезличенные списки одной группы по всем пяти категориям;
- `GET /public/applicants/{number}?year=2026` — заявления и оценка положения;
- `GET /public/faq?question=...` — локальный помощник.

Каталог извлекает из источника только название образовательной программы и код
направления. Объект исходной строки, ФИО, паспорт, СНИЛС, контакты, договоры, результаты
звонков и сотрудник не публикуются. Pending/withdrawn не считаются участниками конкурса.
Новый импорт внутренней системы отражается в публичных данных после обновления страницы
или кнопки «Обновить». Фоновая синхронизация и неподтверждённое время обновления не показываются.

Оценка используется из ядра `rules_v1`: сравнение текущего рейтинга и плана, а не
обученная модель. Ничьи на границе выделяются отдельно. Приказ о зачислении не заменяется прогнозом.
Чат не вызывает внешних ИИ-провайдеров и не требует API-ключа. Текст сообщений не
интерпретируется как HTML. Пользователю предлагается не вводить в чат персональные данные.

Демонстрация включается только явным `?demo=1` или кнопкой «Посмотреть пример»;
на странице всегда есть предупреждение о вымышленных номерах и баллах.

## Проверки и артефакты

```bash
.venv/bin/python -m pytest -q
cd frontend
npm run build
npm run format:check
cd ..
.venv/bin/python tests/browser_portal.py
.venv/bin/python tests/browser_smoke.py
```

Браузерные проверки используют `requirements-browser.txt` и Chromium, создают временные
базы с синтетическими данными и останавливают тестовые серверы. Настройка описана в FRONTEND.md.

- `artifacts/applicant-home.png` — первый экран;
- `artifacts/applicant-home-full.png` — вся главная;
- `artifacts/applicant-mobile.png` — мобильный вид;
- `artifacts/applicant-search.png` — поиск и оценка;
- `artifacts/applicant-rankings.png` — конкурсная таблица;
- `artifacts/bgtu-admissions-portal.zip` — исходники обоих сайтов, сборка, тесты и документация.

Все изображения сняты в демо-режиме. Исходная персональная выгрузка, рабочие БД,
секреты и установленные зависимости не входят в ZIP и Git.
