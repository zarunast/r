# Результаты проверки

Проверка выполнена в текущей Linux-среде на Python 3.12.14.
Заявленная минимальная версия кода — 3.11; отдельный прогон на Python 3.11 не выполнялся.

## Настоящая выгрузка

Входной файл пользователя `выгрузка.xlsx`, один лист, 19 610 строк данных, 60 столбцов.
Первый импорт: **3 506 новых абитуриентов, 19 610 новых заявлений, 0 ошибок**.
В базе 301 группа по сочетанию направления, кампании, формы и квоты.

Итоговая реализация повторно проверена двумя последовательными загрузками того же файла:
в обоих случаях **0 новых/обновлённых абитуриентов, 0 новых/обновлённых заявлений,
19 610 неизменённых заявлений, 0 ошибок**.
Импорт занимал примерно 7–9 секунд на полный файл. Это наблюдение данной среды,
не нагрузочная гарантия и не выполнение норматива ТЗ для произвольных файлов.

Обнаружено расхождение персональных полей одного абитуриента между строками:
импорт предупреждает и использует последнюю строку без вывода персональных данных в отчёт.
Персональная база проверки хранится локально в игнорируемом `data/`, не входит в ZIP.

## Автоматические сценарии

`python -m pytest -q`: 21 тест. Проверены:

- повторная загрузка и обновление баллов, несколько заявлений одного человека, новый год;
- ошибки строк, дубли, текстовые идентификаторы и алиасы столбцов;
- пять категорий без изменения баллов, ничьи и пограничный прогноз;
- сохранение локальных данных родителя и стабильность конфликтующих строк;
- переходы договора, журнал изменений, повторная оплата, DOCX с разорванным маркером;
- окна обзвона, резервное копирование с чтением восстановленной копии;
- защита Excel от формул, PDF с кириллицей;
- откат транзакции, JWT, запрет доступа извне локальной сети;
- публичные ответы без персональных полей, поиск кириллицей, безопасный поиск с SQL-метасимволами;
- зачисление, сохранение номера приказа после повторного импорта, JSON/XML-пакет 1С.
- защищённые методы дашборда, каталог групп, внутренние рейтинги с ФИО, фильтры реестра/договоров;
- атомарное создание карточки и заявления, журнал только успешных операций и явный UTC.

Тестовый клиент в этой среде требует разрешённой работы локальных сокетов.
Два предупреждения зависимостей: переход Starlette TestClient с httpx на httpx2 и
устаревающий модуль crypt в passlib на Python 3.12. Сбоев тестов нет.

## Первичная проверка сервера ядра

Uvicorn запущен отдельным процессом с временной БД и временным JWT-секретом,
после проверки остановлен. Через настоящие локальные HTTP-запросы проверены:

- `/health`: 200 и успешный запрос к БД;
- `/openapi.json`: 200, 23 пути;
- `/public/rankings`: 200, пять списков;
- `/applicants` без JWT: 401.

`pip check`: несовместимых зависимостей не обнаружено.
Не проверялись 500 параллельных запросов, инфраструктура вуза, юридический шаблон,
реальная конфигурация 1С, обученная ИИ-модель, автоматический cron и восстановление в новой облачной задаче.

## Внутренний сайт, версия 0.2

React 18.3.1, TypeScript 5.7, Vite 6.4.5, Node.js 24.19.0.

- `npm run build`: успешно, включает строгую проверку TypeScript.
- `npm run format:check`: успешно.
- `python tests/browser_smoke.py`: успешно в Chromium, без ошибок JavaScript.
- Desktop 1440×1000 и mobile 390×844: нет горизонтального переполнения страницы;
  широкие таблицы прокручиваются внутри своего блока.

Браузерный тест использует отдельную временную SQLite-базу и проверяет:
демо-навигацию, поиск, редактирование карточки, пустую квоту, изменение плана мест,
сохранение результата звонка, загрузку CSV, мобильную навигацию, вход в настоящий
API, создание карточки и заявления одной транзакцией, импорт ЕПГУ через форму,
изменение этапа/места договора, импорт подтверждения оплаты, скачивание и чтение
конкурсного XLSX, выход из системы. Проверены реальные HTTP-запросы между браузером
и Uvicorn; сервер теста после завершения остановлен.

Файлы `artifacts/dashboard-desktop.png`, `dashboard-mobile.png`, `rankings-desktop.png`
и `login-desktop.png` сняты на вымышленных данных, не содержат данных исходной выгрузки.
Значения демо-дашборда соответствуют макету и не являются подсчётом реальных абитуриентов.
